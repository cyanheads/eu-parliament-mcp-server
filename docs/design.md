# eu-parliament-mcp-server — Design

## MCP Surface

All nine tools are read-only and idempotent. Use `readOnlyHint: true`, `idempotentHint: true`, `openWorldHint: true`; omit `destructiveHint`. Static reference topics alone use `openWorldHint: false` only if separated into a wholly offline definition; this consolidated reference tool remains open-world. No resource or prompt definitions, apps, client round trips, or SQL workspace are needed: every workflow is reachable through tools. The published `eu-parliament-guide` skill is served as `skill://eu-parliament-guide/SKILL.md` through `createApp({ skills })` (the SDK skills extension) and carries the cross-tool gates: term calendar, final-vote selection, voter country on a date, identifier chains.

| Name | Description | Key inputs |
|:---|:---|:---|
| `euparl_list_reference` | List parliamentary codes, identifier formats, committees, political groups, and coverage limitations; resolve organization IDs. | `topic`, `organization_ids`, paging |
| `euparl_list_procedures` | List procedure references by procedure type. Titles, stages, and participants require a procedure lookup. | `process_type`, paging |
| `euparl_get_procedure` | Read a procedure's title, stage, events, participants, and linked parliamentary documents. | `procedure_id`, `language`, `section`, paging |
| `euparl_search_documents` | Search adopted texts by keywords, list committee or plenary documents by supported filters, or read a document by its canonical identifier. | `mode`, `source`, `document_id`, filters |
| `euparl_search_speeches` | Search plenary speech records by keywords, speaker, or sitting date and read their metadata and source-document links. | `mode`, `speech_id`, filters |
| `euparl_search_meps` | Find MEPs by country, group, gender, term, or mandate date; filter names locally over the complete selected roster. Defaults to members in office today. | `name_contains`, `term`, `mandate_date`, filters |
| `euparl_get_mep` | Read an MEP's identity and membership history, including committees, delegations, and political groups. | `mep_id`, `section`, paging |
| `euparl_get_plenary_votes` | Discover plenary sittings by year, inspect sitting decisions, or page voters for one decision. Recorded and intended votes remain distinct. | `mode`, `year`, `sitting_id`, `decision_id`, `position`, paging |
| `euparl_list_questions` | List parliamentary questions by year and type or read a question and its answer references. | `mode`, `year`, `work_type`, `question_id` |

## Overview and requirements

Wrap the European Parliament Open Data REST v2 API for legislative analysts, journalists, compliance researchers, and parliamentary research. The workflow is discovery → canonical identifier → detail → linked parliamentary evidence. This server covers Parliament records, not enacted-law completeness or a member's lifetime voting history.

- Keyless public GET requests to `https://data.europarl.europa.eu/api/v2/`; always send `format=application/ld+json`, `Accept: application/ld+json`, and a server/version User-Agent. Omitted format returned RDF/XML during verification despite the documented default.
- STDIO and Streamable HTTP; no required stateful session or upstream credentials. The public hosted endpoint is `https://eu-parliament.caseyjhand.com/mcp`. No user-data writes, live user-data store, native dependency, or downloaded document parser.
- The [OpenAPI specification](https://data.europarl.europa.eu/api/v2/) declares 500 requests per five minutes per endpoint and [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Attribute European Parliament Open Data, link the source and license, and identify normalization as a change. Public caching and redistribution must preserve attribution; no exclusive rights or endorsement are implied. No separate official SDK is required: Web fetch plus Zod covers the advertised REST interface.
- Preserve the API's uncertainty and exact identifiers. No guessed CELEX, inferred legal effect, invented zero tally, current affiliation substituted for historical affiliation, or missing text presented as a full transcript.

## User goals and workflow analysis

1. Discover a legislative file through adopted-text search or procedure catalogue, then inspect its timeline and participants.
2. Follow a procedure's document identifiers to committee opinions, plenary reports, and adopted texts.
3. Resolve a member by name, country, parliamentary term or mandate date and inspect membership intervals.
4. Discover sittings, inspect decisions, and retrieve every recorded or intended voter position.
5. Search speeches and inspect parliamentary questions and answer links.
6. Obtain source identifiers and references for independent legal research.

| Workflow | Service sequence | Cost and completeness |
|:---|:---|:---|
| Name resolution | Fetch complete current, dated, or term roster with omitted paging → normalize → strict token filter → local page | Never filter a partial roster; no per-hit detail lookup |
| Procedure evidence | One procedure detail → select overview or one complete collection page → document detail on demand | Embedded events/participations avoid N+1 enrichment |
| Voting research | Meeting list → whole sitting decisions → local summary page → one rich decision or voter position → optional explicit historical-term roster join | No sitting-wide person-by-person request fanout; missing names remain unresolved IDs |
| Document/question reading | Family list → canonical detail → selected-language expressions and source-file links | Source files are linked, never fetched or parsed |

## Shared schema and paging contract

Use flat `z.object` input and output roots for client compatibility. Every field, nested array item, and enum has `.describe()`. Wrap every optional string with `z.preprocess(value => typeof value === 'string' && value.trim() === '' ? undefined : value, schema.optional())`; the inner schema retains its advertised validation. Check parsed values, never key presence, and never spread input into query parameters. Required identifiers use nonblank `.min(1)` plus a pattern accepting each documented URI/prefix/reference form; validate calendar dates as real dates and numeric IDs as decimal strings. Required `topic`, mode and section discriminators stay enums. Reject incompatible mode fields before any request. Types below are required unless marked `?`; outputs are flat objects with a `mode` discriminator and optional mode-specific arms, enforced in handlers.

Filter codes accepting case variants or aliases (`language`, `process_type`, `country`, `political_group`, `gender`, `work_type`, `activity_type`) are advertised as strings with canonical values and accepted aliases in `.describe()`, not canonical-only enums that reject aliases before the handler. After blank preprocessing, the handler trims code whitespace, normalizes case/explicit aliases, then validates a source-specific allowlist before HTTP; unsupported values fail `invalid_filter`. Do not normalize free-text search strings or third-party output. Canonical-only mode/section/position enums advertise no aliases. Reference topics enumerate canonical filter values and their accepted spellings.

| Shared input | Type / default | Meaning |
|:---|:---|:---|
| `language` | supported EU ISO-639-1 code string, default `en` | Normalize case then validate the 24-language allowlist; select localized fields, never translate |
| `offset` | integer ≥0, default 0 | Start of an upstream list or explicitly named local collection |
| `limit` | whole number ≥1, default 20; no advertised maximum while clamping | Return requested whole items or remaining local rows; bounded upstream modes normalize with a notice. `EUPARL_CLAMP_LIMITS=false` enforces the largest bound only when every tool mode is bounded |

Acquisition bounds live beside `pageWindow` in `eu-parliament-normalization.ts`, feeding effective limits, schemas, normalization notices and reference coverage:

| Collection | Acquisition / caller limit |
|:---|:---|
| Process-type procedures, complete rosters, memberships, procedure sections, decisions, voters, static reference tables | Requested count or remaining rows; no output-size cap |
| Non-keyword adopted texts and speeches | Aligned 100-row upstream pages; caller pages can span requests |
| Unfiltered procedures, questions, committee/plenary documents, keyword adopted texts and speeches, live reference bodies, sittings | 1000 per request |
| Organization lookups | 20 paced requests per call |

Local page limits normalize only to `Number.MAX_SAFE_INTEGER`, keeping very large finite integer requests valid in output metadata. Whole rows and relation arrays remain complete, with no rendered-character budget. All internal requests share one operation deadline. Non-keyword adopted texts send `sort-by=doc-id:asc`; speeches send `sort-by=sitting-date:asc,numbering:asc`. Aligned upstream offsets are multiples of 100 regardless of caller offset or limit; the service slices only the overlapping rows and continues across boundaries. The fixed size limits overfetch on a default 20-row request while retaining the geometry verified stable upstream. Text or title keywords keep upstream relevance order and disclose possible repeats or omissions on both surfaces.

List outputs use `{items: T[], page: {offset, limit, returned, has_more, next_offset?}}`. `next_offset` exists when another page is reachable. For lists without an upstream total, a full page means `has_more: true` until a subsequent empty page proves exhaustion; never invent a total. Speech and adopted-text searches and procedure listings without `process_type` expose a 10000-result window: the effective limit is `min(limit, cap, 10000 - offset)`, disclosed with a notice when the window narrows it, and an offset of 10000 or more fails `invalid_filter` with a service-supplied hint to narrow the filters. At that window boundary, `has_more` can remain true while `next_offset` is omitted: a notice directs the caller to narrow supported filters. Parliament serves each `/procedures` list request from one of two complete orderings of the same set, picked per request whatever the parameters, so pages reached through upstream offsets repeat some procedures and omit others. Unfiltered procedure pages keep upstream paging and carry a notice saying so; a listing with `process_type` is a local collection (below). An upstream total of 10000 or more on those endpoints is a lower bound, never exact `totalCount`. Smaller upstream totals and collection totals computed over a completely fetched set are exact. `ctx.enrich.truncated({shown, cap})` discloses partial results. Enrichment declares `effectiveQuery`/`appliedFilters`, optional `notice`, and optional exact `totalCount`, with complete trailer renderers for structured fields. Empty results remain success, with the notices below. Those no-match notices fire only at offset 0 on upstream-paged lists (speeches, documents, unfiltered procedures, questions, sittings, live reference bodies): an empty page past offset 0 says “The page at offset N returned no {noun}. Restart at offset 0 or return to the previous page.” and nothing about earlier pages, because a 204 carries no total. Local pages at or beyond a positive complete total disclose the offset, exact total and recovery to offset zero or the previous page, after snapshot validation. Genuinely empty collections retain domain guidance; in-range pages gain no past-end notice. Static reference tables follow the same rule.

Local collections retain upstream order except MEP name results (stable sort by `sortLabel`, then identifier), `process_type` procedure listings (`procedure_id` in code-unit order, unique within a complete acquisition) and procedure sections. The upstream returns the same procedure records and relation arrays in varying order between identical requests, so procedure events and participants sort by `date` ascending with undated records last, then `id`, then the serialized record (a total order); documents sort by `document_id`; and their nested ID arrays (`document_ids`, `sitting_ids`, `person_ids`, `organization_ids`) sort by value. The slice uses the order the snapshot hashes: hashing a sorted copy while slicing upstream order would let two matching snapshots slice different orders and silently repeat or skip records. Local paging must never slice strings or silently drop rows. Include `snapshot` (SHA-256 of the normalized complete selected collection plus normalized scope, filters, language and retrieval mode) in `page`. Input `snapshot` is optional at offset 0 and required for local offset >0; missing continuation snapshots fail `invalid_mode_fields`, checked before any request. Re-fetch the collection on continuation and compare before slicing; a mismatch fails `snapshot_changed`. Hash the actual returned fields, including names when resolved, rather than IDs alone. Apply this rule to procedure sections, memberships, decisions, voters and complete-roster results; static reference tables and upstream-offset lists need no snapshot. A `process_type` procedure listing returns and checks a snapshot the same way, but accepts a continuation without one at any offset: its `procedure_id` order is deterministic for an unchanged set, so an unchecked continuation is correct unless the type gains or loses a procedure between calls, and the snapshot adds only that change detection. This is a stateless drift check, not a retained snapshot or upstream consistency guarantee; no handles, cache, TTL or stored roster are needed.

`LocalizedText = {value: string, language: string}`. Prefer requested language; when absent, select English, then lexicographically first available key, and disclose the actual language plus an enrichment fallback notice. If no value exists, omit the field. Preserve language maps only where explicitly returned; never fabricate an English string. IDs are strings, including numeric person identifiers. Domain URIs and codes returned upstream remain open strings.

`Link = {url: string, media_type?: string, language?: string, issued?: string, size_bytes?: string}`. Resolve relative `distribution/…` paths against `https://data.europarl.europa.eu/`, not the API prefix. Return all expressions matching the chosen available language, all their manifestations, and their unmodified file links. Numeric byte sizes encoded upstream as strings remain strings. No caller-controlled URL is fetched.

Third-party text fields are titles, labels, names, comments, references, and any published text. Render exact strings with reversible JSON quoting when Markdown would alter them. Render link values as usable Markdown links and preserve every scalar and array entry on both `structuredContent` and `content[]`; use field-presence rendering for every optional arm. Enrichment reaches both surfaces through framework rendering. Do not summarize one surface or dump unvalidated raw JSON-LD into output.

## Tools — detail

### euparl_list_reference

| Parameter | Type | Mapping / notes |
|:---|:---|:---|
| `topic` | enum `committees`, `political_groups`, `organizations`, `procedure_types`, `document_types`, `question_types`, `activity_types`, `mep_filters`, `identifiers`, `coverage` | Required; historical bodies use `/corporate-bodies` with verified `body-classification`; organizations resolves supplied IDs; other topics are explicit tables derived from OpenAPI |
| `organization_ids` | optional string array | Required and nonempty only for organizations; decimal IDs or case-sensitive codes matching `[A-Za-z0-9][A-Za-z0-9_-]*` (`IMCO`, `S-D`, `ep-9`, `EU_PARLIAMENT`), bare, with org/ prefix or as exact public organization URIs; case preserved; preserve order and duplicates |
| paging, language | shared | Static tables are paged locally; bodies use upstream offset/limit |

Output `{topic, items: {code, label?: LocalizedText, name?: LocalizedText, id?: string, classification?: string, start_date?: string, end_date?: string, description?: string, found?: boolean, organization_id?: string, source_url?: string}[], page}`. Bodies retain `org/{id}`, identifier and classification, with full selected-language name from `prefLabel` and optional temporal dates; no guessed mapping between organization IDs and API filter codes. Organization lookups page the supplied IDs before fetching `/corporate-bodies/{id}`, with an effective maximum of 20 per call and a shared deadline. `organization_id` is the supplied identifier after trimming and stripping the exact public origin and `org/`, decimal or code, in its supplied case. Codes are case-sensitive upstream (`imco`, `s-d`, `EP-9` return 404), so a miscased code is sent as given and comes back `found: false`. Per-item 204/404 misses return `found: false`; operational failures remain errors. Repeat the same ID list with the returned offset; no snapshot or retained cache. Historical committee/group lists keep their scope and a verified acquisition bound of 1000; static topics have no output-size cap. `mep_filters` documents canonical query tokens including `S-D`, `VERTS-ALE`, `THE-LEFT`, `RENEW`, and observed `PFE`/`ESN`, distinguishing documented and observed values. `document_types` identifies each supported family. `coverage` states speech/committee-filter limitations. Empty notice: “No reference entries matched. Call euparl_list_reference with topic identifiers to inspect accepted identifiers.” Incompatible organization fields fail `invalid_mode_fields`; labels (`S&D`, `GUE/NGL`, `The Left`) and unsafe forms (`org/../5144`, `%35`, `5144?x=y`, a foreign origin) fail `invalid_filter` before HTTP.

### euparl_list_procedures

| Parameter | Type | Mapping / notes |
|:---|:---|:---|
| `process_type` | optional code string from OpenAPI `process-type-list` | Uppercase known code spellings; maps to `process-type`; selects the complete local listing |
| paging | shared | `/procedures`; no keyword, committee, stage, or year filter. Upstream offset and limit with the 10000-result window without `process_type`; a local page of the complete set with it |
| `snapshot` | optional string | `process_type` listings only, optional at every offset; compared when supplied; without `process_type` fails `invalid_mode_fields` before HTTP |

Output list row `{procedure_id, reference?: string, process_type?: string, source_url}` from `process_id`, `label`, `process_type`, and canonical URI. No title enrichment. With `process_type`, each call sends one GET `/procedures?offset=0&limit=10000&process-type={type}`, sorts the rows by `procedure_id`, and pages them locally with `page.snapshot`; `totalCount` is the acquired set size. A response holding fewer distinct procedures than its `meta.total`, a repeated procedure, a total at the 10000-result window, or a full window without a total fails `upstream_paging_stalled` and is never paged as complete. The largest type, RSP, returned all 6,677 rows in 1,001,609 bytes (2026-11-02). Without `process_type`, every page adds the notice “Parliament serves each page of the unfiltered procedure listing from one of two orderings, so pages reached through next_offset can repeat some procedures and omit others. Set process_type for a complete walk in procedure_id order.” Empty notice: “No procedures matched. Remove process_type or call euparl_list_reference with topic procedure_types.” Domain errors: `invalid_filter` for a nonblank unsupported type or an unfiltered offset of 10000 or more; `invalid_mode_fields` for `snapshot` without `process_type` (recovery “Remove snapshot, or repeat the call with the process_type of the listing that returned it.”); `snapshot_changed`; `upstream_paging_stalled`; shared recovery table applies.

### euparl_get_procedure

| Parameter | Type | Mapping / notes |
|:---|:---|:---|
| `procedure_id` | string | Accept `YYYY-NNNN[A-Z]?`, `YYYY/NNNN[A-Z]?`, optional `(TYPE)`, and exact public procedure URI; normalize to path ID and validate optional type against returned type |
| `section` | enum `overview`, `events`, `participants`, `documents`, default `overview` | Avoid returning every embedded collection on an overview call |
| language, paging, snapshot? | shared | Paging applies to selected collection; overview rejects nonzero offset |

GET `/procedures/{id}`. Output `{found: boolean, procedure_id, reference?: string, title?: LocalizedText, process_type?: string, stage?: string, source_url, section, available_sections?: {name: string, count: number}[], events?: Event[], participants?: Participant[], documents?: DocumentRef[], page?}`. Overview carries scalars and section counts; re-calls return all items in selected collection through pages. A found-false result omits section counts and data collections.

`Event = {id, date?, activity_type?, stage?, document_ids: string[], sitting_ids: string[]}` from `consists_of` (`activity_id`, `activity_date`, `had_activity_type`, `occured_at_stage`, relation references). `Participant = {id, person_ids: string[], organization_ids: string[], role?, date?, stage?, political_group_id?, represented_organization_id?, term_id?}` from `had_participation`; never replace these historical groups with current groups. `DocumentRef = {document_id, source_url}` from `created_a_realization_of` and event document relations, deduplicated by canonical ID. Events and participants page in date order (undated last, ties by `id`), documents by `document_id`, and nested ID arrays by value, per the local-collection ordering rule above. Titles/COM references are not available in these references; do not fetch every linked document or derive CELEX. Optional empty arrays represent parsed absent collection relationships, not proof no parliamentary activity occurred. 204/404 detail → `not_found` result with `found: false`, normalized identifier, and enrichment routing to `euparl_list_procedures`. Successful results carry `found: true`.

### euparl_search_documents

| Parameter | Type | Mapping / notes |
|:---|:---|:---|
| `mode` | enum `search`, `get`, default `search` | Flat schema; get requires document_id and forbids search filters |
| `source` | optional enum `adopted_texts`, `committee`, `plenary` | Search-only; omitted search defaults to adopted_texts and echoes it; get rejects an explicit source |
| `document_id` | optional canonical string | Required for get; `eli/dl/doc/…` or exact public URI accepted, strip only known prefix |
| `text`, `title` | optional strings | Only adopted_texts; map exact keys and always send `search-language=language` |
| `year` | optional four-digit integer | adopted_texts/plenary only |
| `term` | optional integer 0–10 | adopted_texts/committee only; `parliamentary-term` |
| `work_type` | optional family-specific code string | Validate against selected family's reference list |
| `sitting_date`, `sitting_date_end` | optional ISO dates | adopted_texts only; end requires start, ordered range |
| `related_process_id` | optional procedure ID | adopted_texts only; normalize as procedure ID |
| language, paging | shared | Adopted list uses `view=list`; non-keyword lists sort by `doc-id:asc` through fixed aligned pages |

No `committee` input: documented AFET/AFCO/ECON queries returned 204 despite unfiltered committee records. A catalogue filter with unknown value semantics cannot be promised; procedure-linked committee documents remain accessible by ID. No keyword filter on committee/plenary; reject rather than ignore it.

Output `{mode, source?, items?: DocumentSummary[], page?, found?: boolean, document?: DocumentDetail}`. Summary `{document_id, identifier?, label?, work_type?, source_url}`: list payloads do not reliably include title, date, author, or linked procedure. Detail adds optional `title: LocalizedText`, `date`, `term_id`, `creator_ids`, `procedure_ids`, `parent_document_ids`, `adopted_document_ids`, `based_on_document_ids`, optional `public_register_ref`, and `links: Link[]`. Map `adopts`, `based_on`, and `notation_publicRegister` without inferring procedure relationships; preserve published relation order, identifiers and media types. Parse `is_realized_by` expressions → `is_embodied_by` manifestations → `is_exemplified_by`. Every get reads generic `/documents/{id}` for every field, independent of the search family; returned document IDs are valid inputs but their targets may be missing or fail upstream. Generic records carry no procedure relation for adopted texts, plenary and committee documents; their family records publish it in `inverse_created_a_realization_of`, beside sitting `eli/dl/event/…` items on adopted texts. When the generic `work_type` is in the `adopted_texts`, `committee` or `plenary` work-type table, one more read of `/{adopted-texts|committee-documents|plenary-documents}/{id}?language=mul` under the generic record's identifier takes that relation's `eli/dl/proc/` entries into `procedure_ids`, after the generic ones, canonical, deduplicated, in published order. Other work types (questions, answers, `CRE-`/`PV-` items, `AMENDMENT_LIST`, `ACT_FOLLOWUP`) and records without `work_type` stay one request. The family read is one attempt inside the shared deadline: 204/404 adds nothing silently; any other classified failure (each 4xx, 429, 5xx, timeout or deadline, malformed body, another record's identity) returns the generic answer with the notice “The procedure relation could not be read from the {family} family record of this document, so procedure_ids may be incomplete; repeat the same get to retry.” Caller cancellation and unclassified throws propagate. Generic GET was verified for committee work, speech subdivision, question and answer. Speech subdivisions may lack expressions; map `is_part_of` to parent_document_ids so the parent is reachable without guessing. Get 204/404 returns found false. Detail does not claim to return document body. Empty notice: “No documents matched. Remove a named filter, or call euparl_list_reference with topic document_types; keyword search is available only for adopted_texts.”

### euparl_search_speeches

| Parameter | Type | Mapping / notes |
|:---|:---|:---|
| `mode` | enum `search`, `get`, default `search` | Get requires speech_id and forbids filters |
| `speech_id` | optional canonical activity ID string | `/speeches/{speech-id}`; accept exact `eli/dl/event/` prefix/public URI |
| `text`, `title` | optional strings | Upstream keys; always send search-language |
| `person_id` | optional numeric ID string | Normalize `person/` prefix; `person-id` |
| `activity_type` | optional code string from speech OpenAPI | Normalize known code case, validate allowlist; `activity-type` |
| `sitting_date`, `sitting_date_end` | optional ISO dates | Exact range parameters; ordered, end requires start |
| `term` | optional integer 9 or 10, search default 10 | Maps to parliamentary-term; an explicit term is forbidden in get mode |
| language, paging | shared | Speech search has a 10000-result window |

Output `{mode, items?: Speech[], page?, found?: boolean, speech?: Speech}`. `Speech = {speech_id, date?, start_time?, end_time?, title?: LocalizedText, activity_type?, participants: {person_ids: string[], role?}[], document_ids: string[], source_url}` from activity fields, `had_participation`, `recorded_in_a_realization_of`. Linked record is often a multilingual activity label, not spoken words. Do not promise text in search or get output; text search can find records whose body is not returned. No `include-output=xml_fragment` until verified and designed. Empty notice at offset 0 (past it, the shared empty-page notice above): “No speech records matched in term {term}[ (the default)]. Term 9 ran 2019-07-02 to 2024-07-15 and term 10 began 2024-07-16; pass the term containing sitting_date [or, without sitting_date: pass term to search the other term]. Speech records do not cover every date of a term; euparl_list_reference topic coverage gives the dates they cover. Otherwise broaden sitting_date or remove person_id; call euparl_list_reference with topic activity_types.” It never infers or switches the term, so retrieval scope stays the caller's explicit or default term; the term intervals are closed historical facts. Term-9 records start in July 2021 (earlier term-9 dates return 204), a coverage fact kept in the `coverage` reference row rather than the notice because a backfill would falsify it; the notice points to that row, so a term-9 date before July 2021 does not read as a term mismatch. Get 204/404 is found false with a search-tool route.

### euparl_search_meps

| Parameter | Type | Mapping / notes |
|:---|:---|:---|
| `name_contains` | optional string | Local strict normalized token match: lowercase, remove diacritics/punctuation; every token must occur in name; no fuzzy scores. A nonblank value with no letter or digit left fails `invalid_filter` before HTTP with its own recovery hint, since an empty token list would match the whole roster |
| `term` | optional integer 0–10 | Omitted uses `/meps/show-current`, explicit uses `/meps?parliamentary-term=…`; exclusive with `mandate_date` (`invalid_mode_fields`) |
| `mandate_date` | optional `YYYY-MM-DD` string, no schema pattern (like `sitting_date`) | `mandate-date` on `/meps/show-current`, the only route the OpenAPI declares it on. Calendar-checked by the shared date check; a date after the client clock's UTC date fails `invalid_filter` with its own recovery hint (upstream answers a future date with today's roster). Blank is unset; all checks run before HTTP |
| `country` | optional supported ISO alpha-2 code string | Uppercase then validate; UK→GB, the code rosters publish and match for United Kingdom members (the OpenAPI enum's `UK` matches nothing); `country-of-representation` |
| `political_group` | optional code string | Query aliases EPP→PPE, S&D→S-D, Verts/ALE and Greens/EFA→VERTS-ALE, The Left and GUE/NGL→THE-LEFT, Renew→RENEW, PfE and Patriots→PFE; never rewrite historical identities. On a dated roster a code matches only members published under it on that date (THE-LEFT misses 2016 GUE/NGL members, PPE misses 2009 PPE-DE members) |
| `gender` | optional code string `FEMALE`, `MALE`, `NAP`, `NKN`, `NST` | Uppercase then validate; `gender` |
| paging, snapshot? | shared | Local paging after complete fetch and optional name filter |

Output `{items: {mep_id, name?, given_name?, family_name?, country?, political_group?}[], page}`. Fetch the complete selected current, dated, or term roster with offset and limit omitted: all three routes were verified to return full rosters in one request. Output limit affects only local paging, never acquisition. Respect meta.total if present; if an upstream continuation marker or a total larger than returned records appears, traverse its documented continuation using internal pages of 50 under the same deadline and detect repeated pages (`upstream_paging_stalled`). Never silently treat a marked partial roster as complete. Do not hardcode roster size. Echo `scope=current` with the actual `as_of` UTC date, `scope=mandate_date` with `mandate_date`, or `scope=parliamentary_term` with the explicit term; the snapshot covers that scope. Group/country values from `api:*` fields describe returned roster context; dated rows publish the values in force on that date, never inferred for another date. Empty notice: “No MEPs matched. Remove name_contains to browse, relax country or political_group, or call euparl_list_reference with topic mep_filters.” When a dated group search comes back empty upstream, it adds: “On a mandate_date roster, political_group matches only the group code in force on that date; omit political_group and read each member's published political_group.”

### euparl_get_mep

| Parameter | Type | Mapping / notes |
|:---|:---|:---|
| `mep_id` | numeric string | Accept numeric ID, `person/{id}`, exact public person URI |
| `section` | enum `overview`, `memberships`, default `overview` | Membership history is separately paged |
| language, paging, snapshot? | shared | language reserved for published localized values, not transliteration |

GET `/meps/{id}`. Output `{found, mep_id, source_url, name?, given_name?, family_name?, citizenship?, place_of_birth?, section, membership_count?, memberships?: {id, organization_id?, classification?, role?, start_date?, end_date?}[], page?}`. `hasMembership` → `organization`, `membershipClassification`, `role`, `memberDuring.startDate/endDate`; `placeOfBirth` maps as observed, never infer from citizenship. Omitted end dates remain absent, not proof membership is current. With `mep_id`, summaries and rich detail add `mep_position: {recorded, intended}`. Each arm contains all matching `positions`, `unavailable_positions` for omitted arrays, and `availability: published|partial|unavailable` according to whether all, some, or none of its three arrays were published. Preserve conflicting positions and empty published arrays. Empty matches never establish absence from a vote; intended corrections never replace recorded positions. Without `mep_id`, omit this field. Label selection retains published text and its language, including fallback; a missing label does not match, whitespace-only input is unset, and matching text never establishes a final vote.

`Decision = {decision_id, label?: LocalizedText, date?, start_time?, order?: string, method?, outcome?, attendees?: number, favor?: number, against?: number, abstention?: number, document_ids: string[], recording_document_ids: string[], partial_document_ids: string[], vote_item_ids: string[], reference_text?: LocalizedText, comment?: LocalizedText, voter_counts: {position, count}[], source_url}`. Voter counts count available ID arrays; they are not substitute tallies. Absence of a voter array means unavailable; zero-length published array means published empty. Do not infer outcomes from tallies or infer no voters from hand-vote method alone.

`Voter = {mep_id, name?: string}`; preserve all published IDs, positions, intended positions and their order. Names optional. When requested, require roster_term and fetch the complete `/meps?parliamentary-term={roster_term}` with paging parameters omitted. Echo `scope=parliamentary_term`, selected term and sitting date; the name is the published identity in that term roster, not proof of the spelling or affiliation on the vote date. Do not infer a term from the date without a verified source field/calendar, substitute current roster names, or join party/group fields. Unresolved IDs keep their notice in this order: a wrong roster_term is the common cause, so it first says roster_term must be the term containing the echoed sitting date and to retry with that term, then routes any member still unresolved to `euparl_get_mep`. It never switches the term itself. An incomplete or failed roster fetch is an operational failure, never partial enrichment. Cache-free page calls refetch sitting/roster; snapshots detect drift. roster_term without resolve_names=true is invalid; it is forbidden outside voters.

Decisions always fetch the complete `/meetings/{sitting-id}/decisions`; no `vote-results`, ignored vote-method filter, or inline all-voters flag. Filtered summaries and voter positions return the requested whole-item count or remaining rows without a character budget; `mode=decision` retrieves one full rich record, and voter mode retrieves one whole-item position page. Reference text and commentary remain in rich detail, avoiding their repetition across a summary page. Unknown/missing sitting 204 or 404 gives empty decisions with sitting-discovery guidance (“No decision data was published for this sitting.”), which also covers a listed sitting that has none. Decisions start in 2019: every sampled 2014–2018 sitting (106 of 277, all of October–December 2018) returns 404; 9 of 24 sittings in January–April 2019 carry decisions, the first on 2019-01-14; from mid-2019 most sittings do, but days without published votes (2019-07-02 to 2019-07-04, 2019-07-16, 2019-07-17) still return 404 (as of 2026-11). Decision/voters modes with an absent decision fail `decision_not_found`; a missing position array succeeds empty with `available=false` and no exact total, while a published empty array has `available=true` and total zero. Sittings forbids sitting_id/decision_id/position/resolve_names; decisions forbids year/decision_id/position/resolve_names; decision forbids year/position/resolve_names; voters forbids year and requires position. The document and vote-item filters are decisions-only and member lookup accepts decisions and decision. Default false resolve_names is treated as unset outside voters.

When `document_id` (without `vote_item_id`) matches decisions whose vote items hold decisions it did not match, a notice names those vote items with the count left out, five at most with the rest counted, and routes to `vote_item_id`. A filter matching nothing explains why: on a sitting whose decisions carry no decided-on, part-of or vote-item relation (2022–2023 sittings sampled), it says so and points to label_contains with the report citation; otherwise it names the filter that emptied the result, suggesting `vote_item_id` for a `document_id` miss. "No decision data was published" is reserved for a sitting that published no decisions, with or without filters.

## Error contracts

Each applicable definition repeats its error entries inline; no shared exported errors array. Detail misses deliberately use found-false results, not exceptions. Baseline validation, cancellation, timeout, 5xx, and serialization errors bubble through framework classification with safe messages and no raw upstream body.

| Reason | Code | Applies / when | Recovery (literal) |
|:---|:---|:---|:---|
| `invalid_filter` | `ValidationError` | Any filtered tool: unsupported code, incompatible source filter, malformed ID/date, ambiguous citation or an offset of 10000 or more on a windowed search; MEP search also rejects a name filter with no letter or digit and a future `mandate_date`. The window offset, malformed or nonexistent dates, unordered sitting ranges and both MEP checks each carry their own service-supplied hint | “Call euparl_list_reference with topic identifiers or the relevant code topic, then retry with a supported value.” |
| `invalid_mode_fields` | `ValidationError` | Mode tools: missing required or incompatible fields, each with a local hint naming the missing field, removal, supported mode or continuation correction. Document-family rejections likewise name supported filters. Procedure listing: `snapshot` without `process_type`, with its own recovery “Remove snapshot, or repeat the call with the process_type of the listing that returned it.” | “Call euparl_list_reference with topic coverage, then retry the selected mode with its required identifiers.” |
| `snapshot_changed` | `Conflict` | Local-page tools: supplied snapshot differs | “Repeat the same tool call with offset 0 and no snapshot, then use the returned snapshot for continuation.” |
| `decision_not_found` | `NotFound` | Decision/voters: decision absent from complete sitting | “Call euparl_get_plenary_votes with mode decisions and the same sitting_id, then use an exact returned decision_id.” |
| `upstream_paging_stalled` | `ServiceUnavailable` | Complete roster traversal repeats a page before exhaustion; a `process_type` procedure response holds fewer distinct procedures than `meta.total`, repeats one, or reaches the 10000-result window | “Retry the same euparl tool call later; do not treat an incomplete lookup as a complete result.” |
| `upstream_rejected` | `InvalidParams` | Service: upstream 400/403/422 despite validated input; nonretryable | “Call euparl_list_reference for supported filters and identifiers, then retry with a narrower supported request.” |
| `upstream_rate_limited` | `RateLimited` | Service: 429 after bounded retries; retryable | “Wait for the reported retry interval, then repeat the same euparl tool call.” |

`upstream_paging_stalled` belongs only to tools internally traversing complete sets; reference lists page upstream without claiming complete local traversal. Declare service-thrown entries with `thrownBy: 'service'`. Unknown upstream values resulting in 204 stay empty success, since 204 alone cannot distinguish an unsupported value from no matches; local allowlists prevent known-invalid codes before HTTP.

## Services and Test Boundary

| Module | Responsibility |
|:---|:---|
| `src/services/eu-parliament/eu-parliament-client.ts` | Fixed-origin GET, endpoint-specific query allowlists, explicit JSON-LD format, status/body boundary, retry/deadline/pacing |
| `src/services/eu-parliament/eu-parliament-schemas.ts` | Edge parsing of actual data envelopes and sparse noun records, named nested schemas |
| `src/services/eu-parliament/eu-parliament-service.ts` | Accessor/init, domain operations, complete-roster traversal and vote collection retrieval |
| `src/services/eu-parliament/eu-parliament-normalization.ts` | Canonical identifiers, localized strings, relative source links, flat domain records |
| `src/services/eu-parliament/eu-parliament-reference.ts` | Static supported codes, query aliases, reference topic records |
| `src/mcp-server/tools/definitions/<verb-noun>.tool.ts` | Nine definitions with local schemas, contracts, enrichment and complete format twins |
| `src/index.ts` | Direct definition imports and service setup; remove scaffold echo registration |

**Test Boundary: injected fetch at the network boundary.** Construct the client/service with `fetch: typeof globalThis.fetch`; production supplies native fetch. Tests supply a deterministic HTTP-response fake, not a mocked service accessor. A clock/wait/timeout seam at the client handles pacing, backoff and the shared deadline timer with fake timers. Handlers receive `ctx.signal`; propagate it through every fetch, response body read, wait, retry, and roster traversal. Network tests exercise actual URL encoding, allowlists, format negotiation, parsing, normalization, paging, and error mapping through handlers. Small pure normalization tests supplement this boundary.

Fetch and read the body inside one attempt. Inspect status before JSON parsing: 204 → typed empty; 404 → typed missing; 200 requires a validated `{data: [...]}` envelope, optional `@context`, `searchResults`, `meta`; do not assume `@graph`. Nonempty malformed JSON or schema mismatch after complete body read is a nonretryable serialization failure. HTML gateway responses/non-JSON 5xx are transient upstream failures. Drop traces/internal endpoints from error data and logs.

Retry GET on network errors, 408, 429, 500, 502, 503, 504; three attempts maximum, 1s exponential base, capped Retry-After, one shared 40s total call deadline (under the 60s default request timeout of MCP SDK clients). Every headers and body read may use the remaining operation deadline, so a slow finishing read is not aborted and repeated. Deadline exhaustion is terminal. The best-effort document family read makes a single attempt, whose failure leaves the generic answer standing with a notice. The deadline starts at service entry and includes queue waits, sitting/roster acquisition, question candidates, organization lookups, body reads and retries. Incomplete acquisition remains a timeout or operational error, never empty success or a partial complete-roster result. Caller abort and input/schema/programmer failures do not retry. The pacer runs inside retry: one FIFO abortable request every 700ms, pending queue 100, shared across this origin. Queue/deadline exhaustion is classified, never silent. No unrestricted remote URL, document download, persistent mirror, roster cache, speculative concurrent page harvesting, or ambient global fetch replacement in tests.

## Design decisions

- Keep exactly nine workflow tools; mode consolidation provides detail retrieval and sitting discovery without tools that only mirror endpoints.
- Page compact decision summaries and nested voter lists independently; retrieve rich decision fields one decision at a time. Outer-only rich paging still duplicates large records across both surfaces.
- Do not implement DataCanvas or a persistent mirror: this launch is identifier discovery and evidence drill-down, with no SQL workspace, native dependency, or user data lifecycle.
- Return found-false detail misses and successful empty lists deliberately. Empty 204 is ambiguous upstream, so describe publication state without asserting nonexistent entities or invalid filters.
- Defer committee filtering rather than ship a filter with no verified successful value. Procedure-linked IDs preserve committee document retrieval.
- Preserve historical IDs without automatic individual lookups. A roster join is bounded; hundreds of per-person retries are not.
- Acquire full current, dated, and term rosters with omitted paging: each arrives whole in one response within the deadline. Dated rosters were first left out because omitted paging returned 500 and sequential 50-row pages did not reliably fit; once omitted paging returned complete dated rosters, `mandate_date` reused the same complete acquisition. Historical voter name resolution uses an explicit term selector and names-only provenance; no cache or inferred affiliation is needed.
- `mandate_date` is exclusive with `term` and may not pass the client's UTC date: the two selectors use different routes, and Parliament answers a future date with today's roster, which would echo a date the roster does not describe.
- GB is the canonical United Kingdom country code, with UK accepted as an input alias: rosters publish and match United Kingdom members only as GB, although the OpenAPI enum lists UK.
- Separate caller page sizes from acquisition geometry: local collections are already acquired whole, so an output-derived cap saves no upstream work and blocks clients able to store large results. Return all requested whole rows and relation arrays without a character budget. Keep a safe-integer metadata bound; retain the organization's 20-request paced-work bound and verified direct upstream acquisition bounds.
- Non-keyword adopted texts and speeches use aligned 100-row sorted upstream pages because speech equal-key ordering changes with request geometry even when sorting is enabled. Slice caller windows across those pages within one shared deadline. A default 20-row call overfetches 80 rows; 1000 caller rows require ten requests. Keyword searches preserve relevance order and disclose its uncertainty.
- Map `decided_on_a_part_of_a_realization_of` and `inverse_consists_of` as their own arrays and select a vote item's decisions with `vote_item_id`: Parliament links a report's split votes and final vote to it only through these relations, so `document_id` alone missed the final vote. A part-of relation stays separate from `document_ids` because a split vote decides on part of an amendment, not all of it; vote items are arrays like the other relations, though every sampled decision carries one. Matching `document_id` through a vote item's `based_on_a_realization_of` would need `/meetings/{id}/vote-results` (about 635 KB more per call), so the steering notice routes callers to `vote_item_id` instead. A vote item whose embedded date differs from `sitting_id` fails before the whole-sitting download.
- Document get keeps the generic read for every field and adds a family read for procedure relations only. Adopted texts, plenary and committee documents publish their procedure on the family record alone. The full family record runs up to 13.5× the generic one (651,914 against 48,260 bytes for `A-9-2023-0188`), and language fallback needs every expression the generic record embeds, so the family record cannot replace it; `language=mul` drops the embedded expressions (1,166–10,659 bytes across 11 records). Routing follows the generic `work_type` against the search work-type tables, since committee document IDs start with any committee code. The family read is best-effort, one attempt with no retries, bounded by the same remaining operation deadline as every other read; `ACT_FOLLOWUP` (external documents) also publishes the relation but is left out, as its identifier already names the adopted text whose get yields the procedure.
- Organization lookups accept Parliament's codes as well as decimal IDs. Procedures, documents and memberships return codes (`org/IMCO`, `org/S-D`, `org/ep-9`, `org/EU_PARLIAMENT`), and `/corporate-bodies/{code}` serves each with `id` equal to `org/{code}`. The served grammar is wider than the OpenAPI `^[A-Z0-9-]+$` (lowercase `ep-9`, underscore `EU_PARLIAMENT`) and case-sensitive, so input case is preserved and never folded. Labels such as `S&D` are not identities and stay rejected; alias rewriting belongs to query filters, not identity lookups.
- Clamp an oversized `limit` by default and advertise no `maximum` (a call above the cap succeeds with a notice rather than failing `-32602`); `EUPARL_CLAMP_LIMITS=false` enforces a strict `maximum` only for tools whose modes are all bounded; mixed tools keep local modes open and normalize their smaller bounded modes with a notice. Narrow a page that reaches past the 10000-result window rather than rejecting it, so `{"offset":9900,"limit":1000}` keeps returning the last 100 procedures.
- List a `process_type` procedure set whole and page it locally. Parliament serves each `/procedures` request from one of two complete orderings picked per request, so a 10-page COD walk at limit 300 returned 2,751 distinct of 2,972 procedures. A canonical parameter order, a fixed upstream page size, omitting `offset` and an undocumented `sort-by` each still alternated, and pinning a backend with its load-balancer cookies would put routing cookies in a public continuation token. One `limit=10000` request returns a whole type in a single ordering, and sorting by `procedure_id` makes both orderings identical. The price is a full read per page served (2026-11-02): COD 446,059 bytes in a median 1.8 s (one 7.7 s outlier in 25 calls) and RSP, the largest type, 1,001,609 bytes in 3.9 s, against about 15 KB in 0.9 s for a 100-row upstream page, with server peak RSS 146–168 MB against 146–147 MB. Every read shares the remaining 40-second operation deadline, including retries and backoff. The snapshot stays optional because the order is deterministic for an unchanged set and offset-only continuations keep working. Unfiltered listings exceed the 10000-result window, so they keep upstream paging and disclose the overlap on every page.
